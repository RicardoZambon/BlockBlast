# Task 1.8: Rough Unity Prototype Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A rough but playable Classic game on an Android phone, built in Unity on top of the tested engine:
- plain squares
- drag and drop with snapping, a ghost and line highlights
- game over and restart
- a save after every move
- 60 fps with no allocations while dragging

**Architecture:**
- **Engine:** `core/src` stays as it is and becomes a local Unity package. `unity/Packages/manifest.json` points at it with `file:../../core/src`, and its own asmdef keeps it free of `UnityEngine`.
- **Game layer:** everything in `unity/Assets/Game` is one runtime assembly, `BlockPuzzle.Game`.
  - The decisions are pure C# that EditMode tests cover: layout math, snapping, drag state and saves.
  - Thin MonoBehaviours only draw squares and read the pointer.
- **Built from code:** one `GameController` creates every object at runtime. An editor script generates the scene and the project settings, so nothing depends on hand-edited scene YAML.
- **No binary assets:** the squares use a sprite made at runtime.

**Tech Stack:**
- Unity 6.3 LTS (6000.3.x), project from the "Universal 2D" template (URP 2D renderer)
- Input System package
- uGUI with the legacy `Text` component, which needs no TextMeshPro resource import
- Unity Test Framework (NUnit, EditMode and PlayMode)
- Android: IL2CPP, ARM64

**Spec:**
- [Master plan](2026-10-15-block-puzzle-game.md): task 1.8, plus the Phase 1 exit gate.
- [Phase 1 plan](2026-10-20-phase-1-engine-simulator.md): the "Still open for Task 1.8" list at the end.

## Global Constraints

- **Unity 6.3 LTS.** The project lives in `unity/` at the repository root and is created from the "Universal 2D" template (master plan 0.8).
- **Platforms:**
  - Portrait only.
  - Android `minSdkVersion` 25 (Android 7.1), the lowest Unity 6.3 supports, and `targetSdkVersion` 36. The master plan said API 24; Unity required raising it.
  - iOS minimum 15.0 is set now, but iOS builds need a Mac, so they're not in this plan.
- **Performance:**
  - 60 fps on a low-end Android phone (2–3 GB RAM).
  - Set `Application.targetFrameRate = 60`.
  - Don't allocate memory inside the drag loop: pointer move, snap, ghost and highlight.
  - Playable within 3 s of a cold start.
- **Drag feel:**
  - The dragged piece floats about 1.5 cells above the finger and grows to board size while dragging.
  - It snaps to the nearest legal spot, shows a ghost preview and highlights the lines that will clear.
  - A drop on an invalid spot animates the piece back to the tray.
- **Game rules:** the engine is the only source of rules. The game layer never decides whether a move is legal or what it scores; it asks `GameSession`.
- **Engine changes:** none are expected. If one is needed, make it test-first in `core/dotnet` (`dotnet test core/BlockPuzzle.slnx`), keep C# 9 and `#nullable enable`, and keep the golden values unchanged.
- **Game-layer C#:** C# 9, the level Unity compiles.
  - Not allowed: file-scoped namespaces, `record`s, `init` accessors, global usings.
  - Every `.cs` file starts with `#nullable enable`.
  - Runtime code is in namespace `BlockPuzzle.Game`, editor code in `BlockPuzzle.Game.EditorTools`, and tests in `BlockPuzzle.Game.Tests`.
- **Randomness:** never use `System.Random` in game logic. New-game seeds come from `RandomNumberGenerator`.
- **Identity and secrets:**
  - Working title "Block Puzzle", bundle ID `com.yourstudio.blockpuzzle` until task 0.2 picks the real name. Never use "Block Blast" or any other game's name.
  - Offline only.
  - No keystores or secrets in the repo: development builds use Unity's debug key.
- **Commits:** messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **Running Unity from the command line:**
  - Close the Unity Editor first, because it locks the project.
  - In every shell, set:
    ```bash
    export UNITY="/c/Program Files/Unity/Hub/Editor/<6000.3.x>/Editor/Unity.exe"   # the version installed in Task 0
    ```
  - EditMode tests:
    ```bash
    "$UNITY" -batchmode -nographics -projectPath unity -runTests -testPlatform EditMode -testResults "$PWD/unity/Logs/editmode.xml" -logFile "$PWD/unity/Logs/editmode.log"
    ```
  - PlayMode tests: the same command with `-testPlatform PlayMode` and `playmode` in the two file names.
  - Add `-testFilter <Namespace.Class>` to run one fixture.
  - Never add `-quit` to a `-runTests` command.
  - A pass is exit code 0 with `failed="0"` on the `<test-run` line of the results file. Exit code 2 means tests failed. Exit code 1 with "Scripts have compiler errors" in the log means the code didn't compile; any other failure, read the log.

## Review Focus

- **The app is killed during a save:** the next launch must find the previous save or the new one, never a truncated file. A file that is corrupt anyway must start a new game, not crash. *Task 5:* the atomic-write and corrupt-file tests.
- **A second finger, or a second press, during a drag:** it must not start another drag or move the piece. *Task 3:* `TryBegin` while dragging fails. *Task 6:* a second `Press` changes nothing.
- **The app is paused mid-drag** (phone call, home button): the piece must go back to the tray, and the game must not change. *Task 6:* `OnApplicationPause(true)` cancels the drag.
- **Tall phones, tablets and notches:** at 9:16, 9:20 and 3:4, inside the safe area, the board and the whole tray must be on screen and tappable. *Task 2:* `BoardLayout` tests for all three shapes.
- **Release off the board, a tap, or a press held still:** the piece goes back to the tray and nothing is placed.
  - *Task 3:* drop without a target.
  - *Task 6:* the off-board release, tap and hold-still tests.

### Task 2: Layout and snapping

**Files:**
- Create: `unity/Assets/Game/Presentation/BoardLayout.cs`, `SnapFinder.cs`
- Test: `unity/Assets/Game/Tests/EditMode/BoardLayoutTests.cs`, `SnapFinderTests.cs`

**Interfaces:**
- Consumes: `GameSession.CanPlace(int slot, int row, int col)`, `TestGames.Position`, `TestBoards`.
- Produces `public readonly struct BoardLayout`:
  - `const float TrayScale = 0.5f`: tray pieces are drawn at half size.
  - `const float LiftCells = 1.5f`: a dragged piece's bottom edge floats this many cells above the pointer.
  - `BoardLayout(Rect safeWorldRect)`: the visible area in world units, minus notches.
  - `float CellSize`.
  - `Vector2 BoardTopLeft`.
  - `Vector2 CellCenter(int row, int col)`: row 0 is the top row.
  - `void ToGrid(Vector2 world, out float row, out float col)`: distance in cells from the board's top-left corner, so `CellCenter(r, c)` gives `(r + 0.5, c + 0.5)`.
  - `Vector2 TraySlotCenter(int slot)`.
  - `int TraySlotAt(Vector2 world)`: the slot under the point, or -1.
  - `Vector2 TrayPieceTopLeft(int slot, int width, int height)`: where a tray piece's top-left corner goes so that, at `TrayScale`, it is centred in its slot.
  - `Vector2 DraggedTopLeft(Vector2 pointerWorld, int width, int height)`: at full size, the piece is centred horizontally on the pointer, with its bottom edge `LiftCells` above it.
- Produces `public static class SnapFinder`:
  - `const float MaxSnapDistance = 1f`, in cells.
  - `static bool TryFind(GameSession game, int slot, float topLeftRow, float topLeftCol, out int row, out int col)`.

**Layout rules:**
- `CellSize = Mathf.Min(safe.width * 0.92f / 8, safe.height / 13.25f)`.
- From top to bottom, the layout is a stack of 13.25 cells, centred vertically in the safe rect:
  - 1.5 cells for the score
  - the 8-cell board, centred horizontally
  - a 0.75-cell gap
  - the 3-cell tray
- The tray is split into three equal slots across the board's width (8/3 cells each). A slot's centre is 1.5 cells below the top of the tray.
- `TraySlotAt` counts the whole tray band: from the board's left edge to its right edge, and from the tray's top to its bottom.

**SnapFinder algorithm** (the tests fix the tie order):
```
r0 = floor(topLeftRow + 0.5), c0 = floor(topLeftCol + 0.5)
for dr in -1..1, then dc in -1..1:            // upper-left candidates first
    (r, c) = (r0 + dr, c0 + dc)
    skip unless game.CanPlace(slot, r, c)
    d2 = (r - topLeftRow)^2 + (c - topLeftCol)^2
    keep it if d2 < MaxSnapDistance^2 and d2 < best    // strict: on a tie the first candidate wins
```
It allocates nothing.

    - `The_board_and_tray_fit_inside_the_safe_area`: all four board corners, and every slot's outer corners at full slot size (8/3 × 3 cells), are inside the rect.
    - `Cell_size_is_the_smaller_of_width_and_height_limits`: equals `Mathf.Min(w * 0.92f / 8, h / 13.25f)`.
    - `Cell_centres_map_back_to_their_cells`: for all 64 cells, `ToGrid(CellCenter(r, c))` gives `(r + 0.5f, c + 0.5f)` within 1e-4.
    - `Each_tray_slot_is_found_at_its_centre_and_the_board_is_not_a_slot`: `TraySlotAt(TraySlotCenter(s)) == s` for s = 0, 1, 2, and `TraySlotAt(CellCenter(4, 4)) == -1`.

- Produces `sealed class DragController : MonoBehaviour`:
  - `const float GrowSeconds = 0.08f`, `const float ReturnSeconds = 0.15f` and `const float DragThresholdCells = 0.25f`.
  - `void Init(BoardLayout layout, BoardView board, TrayView tray, Func<GameSession> game, Action<PlacementOutcome> placed)`.
  - `bool Press(Vector2 world)`: starts a drag when the point is over a tray piece. The piece lifts to `DraggedTopLeft` of the press point and starts growing, but there's no target yet. A press while dragging or returning is ignored.
  - `void Drag(Vector2 world)`:
    - Moves the piece to `DraggedTopLeft`, growing from `TrayScale` to 1 over `GrowSeconds`.
    - Snapping starts only once the pointer has moved `DragThresholdCells` from the press point. Until then there's no target. A lifted short piece pressed in the tray overlaps row 7, so without this, a held press would show a ghost there.
    - After that, it calls `DragSession.Move` with `ToGrid` of the piece's top-left corner, then `BoardView.ShowGhost`.
    - Allocates nothing.
  - `void Release(Vector2 world)`: uses the target from the last `Drag` and doesn't snap again, so a tap never places.
    - On a target, it places, renders and calls `placed`.
    - Otherwise the piece lerps back to its tray spot and scale over `ReturnSeconds`.
  - `void Cancel()`: the same return, without placing.
  - `bool IsDragging`, `bool IsReturning`.
- Produces `sealed class PointerInput : MonoBehaviour`:
  - `void Init(Camera camera, DragController drag)`.

  - Unity 6000.3.26f1 with Android Build Support: OpenJDK 17.0.18, Android SDK, NDK r27c.

- **Tests:**
  - 58 EditMode and 10 PlayMode tests pass, and the 161 .NET tests are unchanged.
  - Snapping ties and atomic saves were also checked against a code change that breaks them: each failed.
- **Engine in Unity:**
  - The 6 golden deals and the golden first-fit game match .NET exactly.
  - `JsonUtility` keeps the snapshot's 64-bit fields exact, and a game resumed through it deals the same pieces.
- **Android:** a 45 MB development APK (IL2CPP ARM64) builds in about 8 minutes. The download limit is 80 MB.

Decisions made while building:
- **Android minimum API 25 (Android 7.1), not 24.** Unity 6.3 rejects anything lower. The master plan allows raising it when an SDK requires it, and now says so.
- **Exit codes:** a compile error makes `-runTests` exit with code 1 and log "Scripts have compiler errors", not 3.
- **Template name:** Unity 6.3 ships the Universal 2D template as `com.unity.template.2d-cross-platform-2d-6.1.6.tgz`; its package name is `com.unity.template.universal-2d`.
- **Packages removed:**
  - The first project creation stopped at the license check. Unity then merged its default packages into the manifest.
  - Removed: analytics (it would break the no-data-before-consent rule), purchasing (Phase 3 decides), collab-proxy, multiplayer center, navigation, XR helpers and visual scripting.
  - Also removed: the template's 3.9 MB scene template.
- **Licensing:** the Hub from winget is a packaged (MSIX) app, so its sign-in lives in the package's own storage. The Editor gets its license only through the Hub's licensing client, so **keep Unity Hub running for batch-mode runs**.
- **Missing folder:** the real `%LOCALAPPDATA%\Unity` folder was missing, and the Editor needs it.
- **Interface additions:**
  - `EngineChecks.PlayFirstFitMove(GameSession)` is public, for the JSON resume test.
  - `GameController` also exposes `Board` and `Tray`, for the PlayMode tests.
  - A tray slot's `PieceView` is the piece that gets dragged.
- **Unity specifics:**
  - `Is.Not.AllocatingGCMemory()` needs `using UnityEngine.TestTools.Constraints;` and a lambda that returns nothing.
  - `Light2D` is in `Unity.RenderPipelines.Universal.2D.Runtime`.
- **The HUD ignores the safe area.** The board and tray respect it, but a notch can cover the score. Phase 2 replaces the HUD anyway.
- **Seeds in tests:** PlayMode tests start new games with random seeds, and their assertions hold for any tray.
